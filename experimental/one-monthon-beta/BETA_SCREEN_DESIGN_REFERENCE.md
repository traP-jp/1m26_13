# β版 画面設計リファレンス

更新日: 2026-09-04
位置づけ: 本番仕様ではない。画面設計時に比較・検証へ使う資料。

## 使い方

この資料はβ版のレイアウトやコンポーネントを採用するためのものではない。βで試した画面上の工夫、人間の指摘、実ブラウザで確認できたことを、次の画面設計で検討できる形にする。具体的な色、寸法、列数、部品、URL、文言は再決定する。

## 画面設計で保持する観察

### 全体ナビゲーション

- 学習者向けの「探す・ロードマップ・プロフィール」と、運営向けの「作る・管理する」を視覚的に分けると役割を取り違えにくかった。
- PCの左ナビとモバイルの固定下部ナビで、主要画面へ一操作で移動できた。
- 運営操作をホームの大きなパネルから外すと、学習者の主目的である検索が強くなった。
- βの独立した検索入口とロードマップ入口は、元仕様の「一つの検索で両方を見つける」と衝突する。次の設計では両案を比較する。

### ホーム・検索結果

- ホームに検索入力があると、技術名や講習会名が分かっている利用者がすぐ開始できた。
- 絞り込みを結果の直前へ置くと、条件と結果の関係を追いやすかった。
- カード全体を一つの詳細リンクにすると、クリック領域と読み上げ順が明確になった。
- タイトル、概要、年度、担当、開催数は一覧比較に使えた。一方、担当班の短縮マークは複数担当や新しいLectureモデルで誤解を生む可能性がある。
- βの3列・2列・1列切替は横あふれを防いだが、カード方式が一覧走査に最適かは確定していない。比較行との再比較が必要。
- 0件時に条件解除・再試行へ進める必要がある。

### Lecture詳細・Session選択

- 一つのLecture内で複数Sessionを移動できる構造は、同一講習企画の教材を追う用途に合った。
- 通常Sessionの反復ラベルを省き、再放送など例外だけを示すと情報量を減らせた。
- 単一Sessionで階層表示を省略する方法は簡潔だったが、事前・メイン・事後Flowを加えたときも関係が理解できるか再検証が必要。
- βの回番号ナビは「第N回」には機能したが、Sessionは「Web編」「OSINT編」も表すため、自由な名前と`order`に対応する選択UIが必要。
- Resourceは所有するLectureまたはSessionが分かる位置へ置き、同じリンクを画面内で重複させない。
- 学習内容、対象者、前提知識、Resource、完了操作、関連Lecture・ロードマップの優先順位を再設計する。

### Lecture・Session編集

- Lectureを先に作り、保存済みLectureへSessionを追加する流れは、Session 0件を許容するモデルと相性がよかった。
- 初期読込失敗時に空フォームを隠して再試行だけを出すと、未取得値による上書きを防げた。
- 保存後に保存済み内容を確認し、編集へ戻れる導線は有効だった。
- 入力欄の直近に条件を示す短いラベルは理解を助けた。ただし「シリーズ」「回番号」「班」「年度の日時導出」は新仕様と衝突するため文言・項目を作り直す。
- 公開前Lectureは学習者ホームではなく運営管理内で確認する。
- 削除は未設計。βのcascade削除画面と最後のSession削除禁止は参照しない。

### Flow管理・実行

- Flowは講習会登録画面の別名ではなく、独立した案内資産として見つけ、選び、実行し、管理する必要がある。
- `lecture_pre`、`session_main`、`lecture_post`の属性と対象を、作成時・一覧時・実行時に取り違えない表示が必要。
- Lecture全体の前後Flowと、各SessionのメインFlowを一つの時系列として見渡せる表現を検討する。
- 複数Flowから選ぶ一覧、Flow詳細、実行中の現在地、中断・再開、作成・編集画面はβでは十分に検証されていない。

### ロードマップ

- 一覧行全体を詳細リンクにし、公開状態の保存結果を明示する方法は有効だった。
- 完了記録から「完了」「現在地」「次」を導出するため、重複状態を持たずに表示が更新できた。
- βで段階名・説明を削除した結果、基礎・実践などの意味と選択肢を説明できなくなった。次の設計では段階、必須、選択、順番の表現を復元する。
- 縦線、円マーカー、完了色は一案にすぎない。構造理解と読み上げ順を先に決める。
- Markdownコピーは未確定の共有方法であり、画面設計の候補としてのみ扱う。

### プロフィール・バッジ

- 講習会バッジの視覚表現と生成規則は`BADGE_ALPHA_SPEC.md`で別途採用済み。ここではプロフィール内の配置、一覧密度、詳細の開き方、モーションと書き出しの要否だけを画面設計する。
- タブを使う場合、`tablist`、`tab`、`tabpanel`、選択状態、roving tabindex、左右矢印、Home、Endが必要。
- βの3タブと元資料の2タブは競合している。完了履歴、講習会バッジ、ロードマップ達成・進捗をどう分けるかから再設計する。
- 「獲得日」より「受講完了日」のほうが、保存された事実を正確に表した。
- バッジから対応Lectureの詳細へ移動できる導線は有用だった。
- 完了数は表示対象だが、順位・学習時間は表示しない。

### 状態・アクセシビリティ

- 通常、読込中、0件、失敗、再試行、保存中、保存失敗、保存成功、下書き、公開を画面設計に含める。
- 操作結果は操作元の文言・状態変化または近接した通知で伝える。
- 開閉文言、`aria-expanded`、表示内容を一致させる。
- PCと390px幅で横スクロール、フォーカス表示、Tab順、主要操作の見切れを確認する。
- 色だけで現在地、完了、公開状態を伝えない。βの青・緑・赤の意味付けは候補に留める。
- 不要な説明文で設計不足を補わず、操作・状態・結果の判断に必要な文だけ残す。

## 画面ごとに作る成果物

| 画面群 | 最低限検討する状態・分岐 |
|---|---|
| ホーム・統合検索 | 初期、検索中、結果あり、0件、失敗、Lectureとロードマップの混在 |
| Lecture一覧・詳細 | 単一/複数Session、日時未定、Resourceなし、再放送、前年度関係、非公開 |
| Flow一覧・詳細・実行 | 3属性、複数候補、実行前、途中、完了、中断再開、対象消失 |
| Lecture/Session編集 | 新規、Session 0件、下書き、公開、保存中、競合、失敗、保存後確認 |
| Flow作成・編集 | 属性選択、対象選択、構成編集、下書き、プレビュー、公開、版変更 |
| ロードマップ一覧・詳細 | 段階、必須、選択肢、途中進捗、全完了、利用不能Lecture |
| プロフィール | 完了0件、履歴、バッジ、ロードマップ進捗、本人/他者表示 |
